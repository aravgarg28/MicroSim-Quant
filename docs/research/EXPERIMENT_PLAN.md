# Experiment Plan

How every experiment runs, so results are reproducible, comparable, and honest. This is the
operational counterpart of RESEARCH_QUESTIONS.md.

## Seed and randomness management

- Master seed per run; experiment configs specify a **seed list** (`seed_base + i` for
  i < n_seeds) — recorded per run.
- **Common random numbers (CRN):** comparison arms share flow/agent stream draws (same
  `flow/*`, `agent/*` stream seeds) while strategy-side streams differ only if the strategy is
  stochastic (ours are deterministic). Effect: arm differences within a seed reflect the
  treatment, not flow luck; paired tests gain enormous power. CRN validity is *tested*: with
  identical strategies in both arms, paired differences must be exactly zero.
- Pilot runs use a disjoint seed range from production runs (no peeking-then-reusing).

## Configuration discipline

- Experiments are fully described by TOML files under `configs/experiments/` referencing
  frozen scenario files (`configs/scenarios/`) and strategy parameter files.
- Every config file is hashed (SHA-256 of canonicalized content); the hash is in every result
  row. Editing a config after results exist ⇒ new hash ⇒ old results never silently mix with
  new.
- **Calibration/pilot → freeze → production:** pilot phase may tune (session length, spread
  base, harness limits, n_seeds via variance check); the frozen production config is committed
  with a `frozen: true` flag; production results only from frozen configs. This is the
  simulation analogue of train/test separation — parameters may not be tuned on the runs that
  produce headline numbers.

## Execution

- Runner: Python CLI `python -m microsim.experiments run configs/experiments/rq2.toml`
  (EXPERIMENT_INTERFACE.md) fanning out runs over a process pool (n_workers = cores − 1),
  each worker executing single-threaded C++ simulations.
- Progress, failures, and retries logged; a failed run (engine assert) **fails the whole
  experiment loudly** — invariant violations invalidate results, never skip-and-continue.
- Runtime budget check: pilot measures sec/run; experiments are sized to fit overnight on the
  dev Mac (documented in each experiment config header). RQ1's 1,400 runs at (est.) 10–60s/run
  ≈ 4–24 core-hours — feasible; the pilot validates before committing.

## Analysis protocol

- **Estimates:** per-arm means/medians with bootstrap 95% CIs over seeds (10⁴ resamples,
  BCa where stable, percentile otherwise). Seed-level scatter (strip/violin) is shown for
  every headline comparison — summary statistics never appear without their underlying
  distribution (AR-4).
- **Tests:** as pre-registered per RQ (paired Wilcoxon primary, paired t sensitivity, trend
  tests, survival methods for RQ3). Family-wise Holm correction as specified there.
- **Economic vs statistical significance:** every reported effect carries units a trader
  reads (ticks per fill, currency per session, % variance reduction) — CIs that exclude zero
  but are economically negligible are reported as such.
- **Sensitivity analysis (mandatory per RQ):** flow-parameter grid (±50% on λs, placement
  depth), spread base (RQ2), horizon H (RQ3), flow share of the subject (RQ1); results
  presented as robustness tables, and conclusions are downgraded if signs flip anywhere in
  the grid.
- Analysis code: notebooks under `experiments/notebooks/` for exploration; *headline* numbers
  regenerated by scripted `python -m microsim.experiments analyze <exp>` (notebook-free,
  CI-runnable smoke version on tiny n).

## Result storage (schema details in EXPERIMENT_STORAGE.md)

Each run appends: run manifest (seed, config hash, git hash, package/compiler versions,
hardware string, start/duration), per-session metric row(s), and optionally event-level
Parquet (probe fills for RQ3, markout samples) behind a config flag — full event logs only
for a sampled subset of seeds (disk budget).

## Reproducibility contract

`python -m microsim.experiments reproduce <experiment> --seed k` re-runs one arm/seed and
byte-compares metric outputs against stored results (INV-10 end-to-end). CI runs a micro
version (2 seeds, short sessions) of every frozen experiment config — the *pipeline* stays
reproducible even between paper-scale runs.

## Reporting

Findings per RQ live in `docs/research/findings/rqN.md`: pre-registered header (copied from
RESEARCH_QUESTIONS.md) → setup → headline table/figures with CIs → sensitivity tables →
limitations → verdict vs hypothesis. Figures regenerated by script; no hand-edited numbers.
The README links the three findings docs and quotes one headline number each, with CI and the
simulation-scope disclaimer.
