# README Plan

The README is the sixty-second pitch that decides whether an engineer opens a second file.
It is assembled incrementally (each release updates its section) against this fixed skeleton.
Rule zero: **every number in it is measured and linked to its manifest; every claim is
demonstrable from a clean clone.**

## Skeleton

1. **Title + one-liner** (PROJECT_VISION's sentence) + badges (CI, nightly, license).
2. **What this is / what it is not** — 4 bullets each; the not-list (no real money, no live
   data, no profitability claims, no distributed anything) up front where a skeptic looks.
3. **Architecture diagram** — the SYSTEM_ARCHITECTURE Mermaid spine, one paragraph of prose.
4. **Feature summary** — table by area (exchange, simulation, strategies, research, quality),
   each row linking its spec doc. The docs *are* the feature.
5. **Market rules in 30 seconds** — price-time priority, the modify-priority table, fee
   model; link EXCHANGE_RULES.md for the rest.
6. **Quick start** — clone → preset build → run tests → run a scripted demo replay → run a
   micro-experiment from Python; exact commands, copy-pasteable, CI-verified (the E2E job
   literally runs the README commands via a script extracted from this section).
7. **Example experiment** — RQ2 in ~15 lines of Python + one result figure with CI bars.
8. **Benchmarks** — headline table (per BENCHMARK_PLAN reporting format): ops with
   p50/p99/allocs, hardware manifest line, link to METHODOLOGY.md + raw JSON. Baseline vs
   optimized columns once Phase 8 lands.
9. **Research findings** — one headline sentence per RQ with CI and the scope disclaimer;
   links to the three findings docs.
10. **Correctness story** — the 17-invariant / differential-oracle / determinism paragraph;
    test-count and fuzz-hours stated from CI artifacts (measured, like everything).
11. **Limitations** — honest list (flow realism, single venue, latency-model gaps, simulated-
    market scope) — pre-empting the smart skeptic is the strongest credibility move available.
12. **Roadmap + docs index** — where the project is on the release ladder; guided reading
    order for a reviewer with 5 / 30 / 120 minutes.
13. **License, attribution** (MIT; "specifications authored with the maintainer, implementation
    with the implementer, all design decisions logged in docs/DECISIONS.md" — the AI-assisted
    workflow is disclosed, not hidden: the decision log makes it a strength).

## Maintenance rules

- README edits ship in the same PR as the capability they describe (no aspirational README).
- Sections 8–10 are regenerated by scripts (`scripts/readme_bench_table.py`, findings
  excerpts) — hand-edited numbers are banned in generated blocks (guard comment markers).
- Length budget: ~2 screens to the quick start; heavy content lives in docs/ links.
